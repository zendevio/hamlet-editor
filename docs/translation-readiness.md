# Translation readiness for P3

After editing a translation, run `pnpm i18n:records --drafter='{"family":"openai","model":"actual model","date":"YYYY-MM-DD","instance":"actual session or thread id"}'` with the real author identity of the new text (for a person: `{"family":"human","person":"Full Name","date":"YYYY-MM-DD","instance":"actual session or thread id"}`). The writer refuses to record changed text without `--drafter`. Run `pnpm i18n:generate` after changing English, translations or review records, then `pnpm i18n:check`. A source delta with unchanged translated text remains stale through record generation, including when a different drafter argument is supplied. Change the translation or record an actual passing review of the new source before associating it with that text. The checker reuses the runtime FormatJS parser and, even when an early gate fails, writes errors and any available locale diagnostics to `test-results/i18n-readiness.json` (override with `I18N_REPORT`). CI uploads this report. No network or translation service is used.

`src/lib/i18n/locale-status.json` lists all 12 locales. `in-progress` reports every missing key and allows English fallback. Main warns on missing or stale translations and the runtime falls back per key to English, including locale-sensitive parameters. `I18N_RELEASE=1 pnpm i18n:check` (or `pnpm i18n:check --release`) fails on every stale record, and on missing keys in any locale marked `complete`. A complete translated locale requires final review. Separately, release mode requires a current `final` record with a passing independent safety verdict for every safety key present in any shipped runtime catalog, even when its locale is `in-progress`. Main warns about these safety drafts. Phase 3 completed all eleven translated catalogs with current final records, including a third-instance safety review for every safety key. Future changed or unreviewed safety text remains blocked by this gate. Tagged releases and manual dry runs run this gate once, in a Linux job of the release workflow (`i18n-release-gate` in `.github/workflows/release.yml`). Draft creation and the dry-run installer builds both depend on it, so a failing gate creates no draft release and starts no installer build. Unknown keys, missing review records, malformed or empty ICU, missing CLDR categories, em dashes, unsafe Unicode, incomplete contexts and hardcoded copy always fail. Current translations must match the English placeholder/tag contract. Stale targets still get syntax checks, but are excluded from that current-source comparison because the runtime uses English for those keys. All catalog files must appear in both the shared webview runtime map and the native menu catalog map. The webview and native menu use the same generated freshness keys for per-key English fallback. The pinned cardinal category table covers all 12 locales and rejects host changes with an ICU drift diagnostic. Length warnings flag short literal labels above 1.8 times English; they do not reject a translation. Branch tests record Node/ICU versions and render nested selects, exact counts, offsets and plural categories with host-ICU witnesses.

`pilot-status.json` is retained and extended in place, preserving the original source/translation hashes and drafter attribution. Every present translated key has a record. Absent translations are the missing-key list, not invented drafts. New records contain:

- `sourceHash` and `translationHash`: SHA-256 of the exact English and translated ICU source.
- `sourceText` and `translationText`: exact snapshots, checked against those hashes. The generated fresh-key lists exclude translations whose snapshots differ from the current English or target text, after checking their hashes. Both runtimes import only `fresh-keys.generated.json`; `pilot-status.json`, reviewer identities and verdict prose stay out of the production bundle. No hashing service or network is needed at runtime.
- `status`: `draft`, `reviewed`, or `final`. Unreviewed translations remain `draft`; the original pilot snapshots are preserved in the record history.
- `drafter` and `reviewer`: structured identities with a `family` from a closed list, an ISO `date` (`YYYY-MM-DD`) and, for a model, a non-empty `model`. The families are `anthropic` (Claude models, including Opus, Sonnet, Haiku and Fable), `openai` (GPT and Codex models), `google` (Gemini models) and `human`. Any other value, including a differently spelled vendor such as `OpenAI Codex` or `open ai`, fails. A `human` identity requires `person` (the reviewer's name; `model` is optional), and `person` is optional for a model identity (for example the operator who ran it). Independence compares the required non-empty `instance` (the actual session or thread id). Semantic review must use a different instance from drafting, and safety review a third instance. The family and model remain recorded but may match. Changing the model name or date does not establish independence. Add a family to `identityFamilies` in `scripts/i18n-contract.mjs` and to this list only when a model from another vendor actually drafts or reviews. The original pilot authors are migrated as family `openai`, model `Codex (model not recorded)`, preserving their recorded date without inventing a model version, with the honest unknown instance `pilot-2026-10-25`.
- `reviewKind`: `ai`, `human`, or `null`; `semanticVerdict`, `safetyVerdict`, `glossaryVersion`: actual evidence, or `null` before review.

`reviewed` and `final` require a reviewer, passing semantic verdict, glossary version, and `reviewedSourceHash`/`reviewedTranslationHash` equal to the reviewed inputs. Updating only the working hashes cannot preserve approval. `final` describes approval of that key only. It does not claim native review.

`safety-keys.json` explicitly lists the destructive and safety messages, including action labels, consequences, refusals, disk overwrite/delete/restore warnings and Steam warnings. Each has `safety: true` in `contexts.json`. The checker requires a non-empty unique manifest matching those flags and covering the known message families. New safety copy must extend both files. The set currently has 100 keys, including the warning paragraphs and related action labels, help, confirmations and refusals.

For every safety key, `reviewed` and `final` also require `safetyVerdict` to be an object with `verdict: "pass"`, `independent: true`, `sourceHash` and `translationHash` matching its reviewed inputs, a structured `reviewer` identity whose instance differs from both the drafter and semantic reviewer, and non-empty `action`, `object`, `conditions` (including negation), `reversibility`, `scope` (disk versus memory), `codePath` and `workflow`. Record the real third independent check against the actual code and UI workflow. A missing, failed or unresolved verdict blocks approval and locale completion. A stale draft cannot be promoted by marking its locale complete. Approval requires actual recorded review; changing status metadata alone never supplies that evidence.

`i18n:generate` generates message types and the per-locale fresh-key lists; `i18n:check` asserts that both files are current. `i18n:records` adds drafts for present translations without a record, leaves fresh records equivalent, and demotes changed translations to draft with the entire old record under `previous`. When only English changes, it keeps the old source snapshot, hashes, author and review evidence: the record remains `stale-source`, main warns, release fails, and both runtimes use English after freshness generation. An unchanged translation always keeps its author, regardless of `--drafter`. A reviewer who confirms unchanged text against new English must explicitly update the source snapshot and its hash, the reviewed hashes and the actual passing verdict evidence, including an independent safety verdict where required. Every new or changed translation requires the actual structured drafter argument; the previous record's drafter is never carried over to new text, and is kept only in `previous`. The writer never invents absent translations or reviewer evidence. Human records are protected while their English source is unchanged. When the source and translation both change, a human record can be reset with its evidence retained under `previous`. Records whose source key, translated key or locale was removed move to `removed[locale][id]`, preserving their full evidence. When that key is added again, its archived record becomes the oldest entry in the new draft's `previous` chain; when a key is removed again while an archived record exists, the earlier archived record is kept the same way, so repeated removals never discard evidence; archived records do not participate in runtime freshness or readiness gates. The 390 original pilot snapshots retain their hashes and author attribution in current records or `previous` history. Phase 3 approvals refer to actual independent reviews of the current text and source; they do not invent historical approval.

The pseudo-locale is generated deterministically from English by editing only FormatJS literal source ranges, adding accents, about 40 percent expansion and message brackets. It is available only through `window.__h1.catalog('pseudo')` in the dev harness. `catalog('en')` or `catalog('de')` restores a real catalog. No setting or persisted locale id is added. `pnpm build` rejects harness code, pseudo artifacts and bracket markers in `build/`.

The mounted overflow suite is `tests/e2e/overflow.spec.ts`; run it with `H1_OUTPUT_DIR=<evidence folder> pnpm test:h1 overflow.spec.ts`. Chromium and WebKit cover pseudo and all 12 real locales at 800x600 (the window minimum) and 1366x768, plus `ja-pseudo` at 800x600: pseudo text with `lang="ja"` and the CJK typography rules (12px floor, CJK font stack). Pseudo runs also expand the harness game-name table, because class, quirk, trinket and building names grow in German, Russian or Polish. Real catalogs are checked at both viewport sizes. States include every page, dialog and picker, every Town building opened, the save-blocked and Death's Door tooltips, and the startup recovery, unreadable-settings, game-text-failure and settings-write-failure notices.

The detector measures what a user can see and reach: text or controls cut by an ancestor that cannot scroll on that axis, ellipsis or line-clamp truncation, text painted outside its own box, text runs painted over each other in the same layer, controls whose hit test at the centre or four inner points lands on an unrelated element (the occlusion that hid header actions under the page), controls no hit test reaches at all, and content wider than its scroll container or the window. Fixed and sticky boxes over a control count as occlusion; only the active overlay (an open dialog, open popover, tooltip, select or menu content, or the loading overlay, which is marked `data-slot="loading-overlay"`) may cover other controls. A control covered by a box that stays put, such as a toast, is hit tested again after scrolling its scroll containers to place it at their start, centre and end, moving only the axes a user can scroll; if one position clears it, it is recorded as informational `occluded-until-scrolled`, otherwise it fails as occlusion. The window ends every clip chain: it clips fixed content, so a fixed control outside it is reported. Other content scrolls with the document only on the axes a user can scroll: the root's overflow, or the body's when the root's is visible, applies to the window, and `hidden` or `clip` there stops user scrolling (the app sets `overflow-hidden` on both, so its window never scrolls). Content that no legal scroll position of its scroll container or the document reveals, such as content above or left of the scroll origin, is reported as clipped; the reachable range comes from the browser, so right-to-left and reversed boxes are handled. Floating content (bits-ui popovers, selects, menus and tooltips) follows its anchor, the element whose `aria-controls`, `aria-describedby` or `aria-owns` names it: while that anchor is scrolled out of view, the content is measured in the samples where the anchor shows; with the anchor in view, the window clips it. While a modal is open, only the dialog and floating content are measured. Content reachable by scrolling, including a document a user can scroll, is measured at each scroll step instead. The steps use the detector's own rule: a hidden root or body overflow is never scrolled, and while an open select, menu or modal locks the page (bits-ui sets `pointer-events: none` and `overflow: hidden` on body), nothing outside it moves, because the page behind cannot be scrolled. Truncation is recorded as deliberate, and never fails, only when the nearest `title` is not blank and contains the full clipped text (whitespace normalized).

The suite is a gate. Every other finding fails its test unless `tests/e2e/overflow-baseline.json` accepts it for that state, locale, viewport and engine, with a reviewed reason; `pnpm test` and the suite reject an entry without one. `node scripts/overflow-baseline.mjs <evidence folder>` lists new findings and stale entries (CI prints it after H1); Each entry lists its locales, viewports and projects explicitly and accepts only their combinations. `--write` adds each new finding with an empty reason for review, scoped to exactly the runs where it occurred (split into several entries when those runs are not one full block, so no entry accepts an unobserved combination), and removes from reviewed entries every run that ran clean, dropping entries with none left. Evidence is one JSON file per state with the findings, accessibility snapshot and native select options; screenshots are written only for samples with gating findings, or for every sample with `H1_OVERFLOW_SCREENSHOTS=all`. The baseline was seeded on macOS; Linux CI fonts can differ, so the first CI run on Linux must be checked and any platform-specific entry reviewed like any other.

Overflow still needs a person: a passing gate does not approve layout. Browser font APIs do not prove glyph availability; canvas widths and successful font loading are not evidence that every character exists. Host plural categories are recorded per browser. Supported runtime policy: the build targets and README minimums are the release floor; P3 must compare CI Node ICU with each supported webview and obtain packaged evidence before claiming coverage. Linux system CJK fonts, IME, Retina/2x and Windows scaling remain release checks.

P3 also owns glossary/register lints, terminology and morphology decisions, per-language in-context review, the independent safety review records, final translation disclosure (owner wording: machine-drafted and reviewed, not by native speakers, with a report link; not called a beta), the Translation fix issue template and the platform coverage ledger. Only English was complete at P2; Phase 3 now has 575 final messages in each of the eleven translated catalogs, including 100 independently approved safety messages per language. No visual or packaged acceptance is implied by a passing catalog or type check.

Use `pnpm i18n:records --locale=<locale> --drafter=...` to attribute one locale at a time; other locales and their archived history remain unchanged. The About disclosure is part of the source catalog and receives the same review as other non-safety text.

`glossary-keys.json` stores only installed-game string-table keys. Game wording and register samples are read locally into release evidence, not committed as a glossary. Phase 3 records terminology/register findings in each independent language review; exact substring matching is not a substitute for checking inflection and context.
