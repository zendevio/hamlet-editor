## S1 typed-error wording changes (2026-10-25)

Catalog keys added in S1 are English-only during P2. Existing translated pilot text remains unchanged. Error titles, complete reasons and raw diagnostics render as separate blocks. Raw OS and ddsavelib text is unchanged. The table includes newly described fallback errors even where an existing API consumer suppresses the error. All error messages not listed here retain their English wording.

Save, reload, backup, profile switch/load, game/profile path and open-folder error toasts now stay open until closed instead of auto-dismissing. Failures with the same operation, code and parameters reuse one toast with the latest diagnostic and return to the front on retry. Recovery-file, safety-backup and kept-copy notices each keep their own toast until dismissed. Toasts stay expanded so later notices do not collapse recovery information. Rollback failures also log every failed file and recovery location through the existing application log plugin in debug and release builds. Startup settings and game-text failures keep their existing notice and add a complete typed or generic reason before the raw diagnostic.

The native game/save folder dialog titles keep their existing catalog keys.

## P2 closeout: translation readiness (S6)

English message wording is unchanged. The abandon-raid loss row now owns its complete name, colon and amount in one rich catalog message, retaining the game-language span and the same English rendering. Raid inventory amount controls inherit the editor language. Unknown raid difficulty labels follow the editor language; corrected English dungeon, length and difficulty fallbacks and readable mod dungeon ids are tagged English. Resolved game labels use the effective game language.

Dialogs can scroll within the window and their footers can wrap. The header keeps its normal 48px minimum and can wrap status/actions when space runs out. Raid metadata cards can shrink and wrap long words; inventory rows can wrap and compact truncated item names expose the full name in a title. Setup confirmation actions can wrap. The header separator stretches within its own flex line so wrapped actions stay above the page. Settings and Town scroll areas now follow the available height when the header wraps, making the end of each page reachable at 800x600; previously 65px was clipped in English. The mounted 1366x768 English comparison in Chromium and WebKit measured zero differing pixels for the header and Settings. Town differed only in the animated game-running dot (60 pixels in an 8x8 box).

The minimum-window findings are now fixed, and the overflow suite fails on any new one. At 800x600: the hero batch toolbar wraps, so Set Level and Revive stay reachable; the hero list search, filter and sort controls wrap, open filters scroll inside a short pane instead of hiding the list, and the class line truncates with its full name in a title; the hero detail header and its two-column rows (vitals, quirks, equipment, trinkets) stack when the detail pane is narrower than 28rem, so the level picker, Historical flag, Death's Door switch and Add Positive/Negative are no longer cut; the Estate invitation labels wrap inside their columns and the trinket tools wrap below the heading; Town slot labels keep at least 8rem and break long game words; the raid backup action moves below the warning text when the alert is narrow. Truncated hero names and skill names have a title. Compared with screenshots taken before these changes, English at 1366x768 is pixel-identical in Chromium and WebKit for every overflow state except the long-name Estate state, where fixture invitation labels used to overlap each other and now wrap.

All app files remain at zero hardcoded-copy occurrences. Stale per-file exceptions now fail the ratchet, and script exceptions cannot exempt plain markup labels. The nine obsolete S5-review entries were removed. A dev-only expanded/accented pseudo catalog, H1 overflow triage suite, all-locale parity report, CLDR coverage and per-key review-status tracking prepare the source for P3. Incomplete translations keep their English fallback; no new real translation or review approval is claimed.

README language/privacy guidance now explains both language settings, detection and fallback, Linux CJK fonts and the Safari 16.4 minimum. The translation disclosure says translations are machine-drafted and reviewed, but not by native speakers, and links to issues; it is not called a beta. See [translation-readiness.md](translation-readiness.md) for gate behavior and remaining release evidence.
